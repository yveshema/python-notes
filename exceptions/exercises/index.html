Exercises

9.1 — Write a program, safe_divide.py, that reads two numbers from the user and prints the result of dividing the first by the second. Handle bad input (letters) and division by zero separately, with a different message for each. The program must not print a traceback for either, and must print "done" as its last line in every case.

9.2 — Write a function, read_int(prompt), that prompts the user to enter a number and returns it as an int. The function should use exception handling to catch any invalid input, repeated prompting the user until a whole number is entered.

9.3 — Extend the function in the previous question to read_int(prompt, minimum, maximum), such that it also keeps prompting the user until the entered input is within a given range.

9.4 — Write a program, wordcount.py, that takes a filename as a command-line argument and prints the number of lines and words in it. The program should use an exception handling approach to enforce the following constraints:

  • if no filename is supplied, the program prints usage: wordcount.py <file> and exits
  • if the file does not exist, the program prints Error: no such file <file> and exists
  • otherwise, the program prints the counts

9.5 — Write a program, average_file.py, which reads a file containing one number per line and prints the average. Some lines are blank or contain text. The program must:

  • skip unusable lines, reporting each one as line 7: skipping 'abc'
  • still print the average of the usable lines
  • print a clear message if the file has no usable numbers

9.6 — Write a command line tool called sales_report.py, that reads a CSV file of sales and prints a summary. The program should handle all failures gracefully while providing adequate feedback about any failure that occurs.

The CSV file looks like this (the last three rows are deliberately broken):

region,units,unit_price
West,12,9.99
East,5,24.50
North,,9.99
South,abc,9.99
West,3

Spec.

  1. The filename is provided as a command line argument. If not provided, print a usage line and and exit.
  2. Define a function, parse_row(fields), that takes one row as a list of strings and returns a tuple (region, units, unit_price) with the numbers converted. The function should raise ValueError with a suitable message naming the problem for the following cases:
    • too few fields
    • a non-numeric quantity or price
    • a negative quantity
    • an empty region.
  3. Define a function, load_sales(path), that opens the file and calls parse_row for each row (skipping the header row). Bad rows are skipped, counted, and reported by raising a suitable exception. If none of the rows were usable, it raised ValueError. The function should not handle missing file.
  4. Define a function, report(sales), that prints the total revenue, revenue per region (sorted highest-first), and the number of rows included.
  5. Define a fuction, main(). It handles missing argument, missing file, unreadable file, and the "no usable rows" case. For each of these cases, the function should print a suitable message and exit. On success, the function prints a final count of skipped rows if any.
