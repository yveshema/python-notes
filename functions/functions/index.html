User-defined functions

Defining and calling functions

A function packages statements under a name. You define it with def and run it by calling it with parentheses:

def greet():
    print("Hello!")
    print("Welcome.")

greet()          # call it — runs the body
greet()          # call again — reuse!

Parameters and arguments — inputs

A parameter is a named input to the function specified in the definition. An argument is the value you pass when calling the function. They're matched left to right:

def greet(name):             # `name` is a parameter
    print(f"Hello, {name}!")

greet("Ada")                 # "Ada" is the argument → Hello, Ada!
greet("Grace")               #                       → Hello, Grace!

You can specify multiple parameters:

def describe(name, age):
    print(f"{name} is {age} years old")

describe("Ada", 36)

We call these positional arguments (the default); that is, the first argument is assigned to the first parameter (name = "Ada"), the second argument assigned to the second parameter, and so on.

Returning values

The return keyword is used to hands a value back to the caller so the program can use it.

def square(n):
    return n * n             # send the result back

result = square(5)           # result is now 25
print(result)                # ⇒ 25
print(square(3) + square(4)) # ⇒ 25   (use functions in expressions)

If a function does not explicitly return a value, None is returned.

Consider:

def square_bad(n):
    print(n * n)             # shows it, but doesn't return it 

x = square_bad(5)            # prints 25
print(x)                     # ⇒ None

A return also ends the function immediately:

def abs_value(n):
    if n < 0:
        return -n            # exits here
    return n                 # only reached when n >= 0

A function with no return (or a bare return) returns None.

Default parameters

Sometimes it is useful to assign a default value to a parameter at definition time. This makes the parameter optional, meaning the argument may be left out when calling the function:

def greet(name, greeting="Hello"):
    print(f"{greeting}, {name}!")

greet("Ada")                 # ⇒ Hello, Ada!
greet("Ada", "Welcome")      # ⇒ Welcome, Ada!

Default parameters are also called optional parameters. When present, they must come after required parameters.

Keyword arguments — pass by name

You can pass arguments by parameter name, in any order. This can be useful for functions that expect several inputs:

def order(item, qty, order_type="Delivery"):
    print(f"{qty}x {item}, {order_type}")

order("mug", 2)
order("mug", qty=2, order_type="Pickup")      # keyword — self-documenting
order(qty=3, item="pen")                      # order doesn't matter with keywords

order(2, item="mug")                          # ⇒ Error

If positional arguments are used, then ordering matters.

You can force a function to accept only keyword arguments:

def greet(*, name, greeting="Hello"):
    print(f"{greeting}, {name}!")

greet(name="Ada")               # ⇒ Hello, Ada!
greet("Ada")                    # ⇒ Error - only keyword arguments allowed

Docstrings — documenting a function

It is recommended to document every function. If the first line of the body of a function is a triple-quoted string, help(fn) will prints it:

def celsius_to_f(c):
    """Convert a Celsius temperature to Fahrenheit."""
    return c * 9 / 5 + 32

For more complex function, it may be suitable to provide more details in a multi-line docstring, documenting things like expected inputs, return values, how to call the function, etc.

Scope — local vs. global

Names created inside a function are local: they exist only during the call and are invisible outside:

def compute():
    x = 10           # local to compute
    return x

compute()
print(x)             # NameError: name 'x' is not defined

A function can read variables from the enclosing (global) scope:

tax_rate = 0.1                 # global
def price_with_tax(p):
    return p + p * tax_rate

Avoid relying on globals

Using global variables makes it difficult to predict the behavior of your functions. Instead, prefer using parameters and return values which keep functions self-contained and independently testable.

Variable number of arguments

Consider this:

words = ["the", "quick", "brown", "fox"]
print(*words)       # ⇒ the quick brown fox

The built-in print() function accepts a variable number of arguments. If you have a list of words, you can unpack it into the function call using the *args syntax.

To define such a function, the same syntax is used:

def log(*messages, level="INFO"):
    for msg in messages:
        print(f"::{level}:: {msg}")

log("initializing volume", "checking system health", level="DEBUG")

Lambda functions

If you function has a one line body, then it can be defined more concisely using lambda syntax. Supposed you need a function to test if a number is even. You can define it like this:

is_even = lambda x: x % 2 == 0

is_even(3)      # ⇒ False
is_even(6)      # ⇒ True

Lambda functions can be useful in functions that take other functions as arguments:

fruits = ["orange", "avocado", "pineapple", "apple", "banana"]

print(sorted(fruits))                           # ⇒ ['apple', 'avocado', 'banana', 'orange', 'pineapple']

print(sorted(fruits, key=lambda x: len(x)))     # ⇒ ['apple', 'banana', 'orange', 'avocado', 'pineapple']

Recursion

Functions can call other functions. When a function calls itself, this is called recursion. Recursion is often deployed to solve problems that present smaller versions of themselves when broken down.

def factorial(n):
    if n < 0:
        return -1
    if n <= 1:
        return 1
    return n * factorial(n - 1)

print(factorial(5))             # ⇒ 120

Decomposition

Functions enable a style of programming where a complex task can be broken down into smaller tasks that are easier to solve. This works best when each function has a single responsibility.

Suppose you want to find the average daily temperature over a period of several days:

# avg_temperature.py

def read_temps(n):
    """Read n temperatures from the user, return them as a list."""
    temps = []
    for i in range(n):
        temps.append(float(input(f"temp {i+1}: ")))
    return temps

def average(values):
    """Return the mean of a non-empty list of numbers."""
    return sum(values) / len(values)

def main():
    temps = read_temps(3)
    print(f"Average: {average(temps):.1f}")

main()

Almost all programs are written like this. You define small functions, each solving one part of the problem, then compose them to solve the whole problem.
